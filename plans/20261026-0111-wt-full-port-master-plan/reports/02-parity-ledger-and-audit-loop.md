# 02 — Parity Ledger, Test-Port Strategy, Audit Loop (SSOT)

"100% port" = **every in-scope WT source file/symbol has a ledger row in a terminal state AND every in-scope WT test is ported-or-waived AND audit stop criteria (§4) hold twice in a row.**

## 1. Ledger (durable, repo-level, built in P01)

Location: `terminal_gpui/parity/` (NOT under plans/, survives plan archive). **Sharded:** each phase writes only `parity/ledger/pNN-<name>/{files,symbols,tests,decisions}.csv`; `xtask merge` produces the merged `parity/merged/*.csv` (P19-owned, generated). P01 owns schema + seed only; `verified` is written solely by audit reviewers at barriers (no wave running). Golden data: `parity/golden/<kind>-*` owned by the named phase (vt:P03, parser:P04, terminal:P09, render:P10, ui:P14, editor:P17).

| File | Granularity | Seed |
|---|---|---|
| `files.csv` (per shard) | 1 row per in-scope WT source file (`.cpp/.h/.hpp/.idl/.xaml`) | generated: `cargo run -p xtask -- ledger-seed` |
| `symbols.csv` (per shard) | 1 row per public/virtual method of high-risk modules (adapter 134 `ITermDispatch`+8 interact, parser state machine, TextBuffer/Row/ROW, TerminalInput, Terminal, ControlCore/Interactivity, `ActionAndArgs`, `CascadiaSettings`) | generated by regex over headers, then hand-checked in P01 |
| `tests.csv` (per shard) | 1 row per WT `TEST_METHOD` (and per data-row for data-driven suites in P03/P04) | generated: `ledger-seed --tests` |
| `exclusions.csv` (single, P01) | 1 row per OUT-of-scope WT source file with ADR id (ADR-0001); counted by the orphan check | generated by `ledger-seed` |
| `decisions.csv` (per shard) | ADR index: `out-of-scope`, `replaced`, `deviation` rows → `docs/decisions/NNNN-*.md` | manual |

Columns (files/symbols): `id, wt_path[:symbol], wt_loc, module, phase, rust_path[:symbol], status, test_ids, adr, author, reviewed_by, reviewed_at, notes` (`ledger-check` asserts `reviewed_by` != `author` for `verified`).
`status` enum (terminal states **bold**): `not-started` · `stub` (signature, `todo!`) · `partial` · `ported` · **`verified`** (ported + test ids exist + independent review PASS) · **`replaced`** (idiomatic replacement, needs ADR) · **`out-of-scope`** (needs ADR). Only `verified|replaced|out-of-scope` count as done. A worker may set `ported`; only the audit reviewer sets `verified`.
Tests columns: `id, wt_path, wt_suite::method, phase, rust_test (path::fn), status(not-started|ported|passing|waived), adr`. Rust test naming (single rule): `wt_<suite>__<method>` (double underscore, snake-case), where `<suite>` is the ledger-assigned prefix per WT test group (adapter, input, parser, textbuffer, terminalcore, til, types, control, settings, app, cmdline, actions, ui, host, winconpty, connection; native non-WT-ported suites: renderer, uia, editor) so ledger↔`cargo test --list` is mechanically joinable.

## 2. Test-port strategy (parity criterion)

1. Port WT tests **verbatim in intent** (same inputs/expected values) into Rust integration tests per crate `tests/wt_*.rs`. Expected values are copied from WT, never recomputed from Rust output.
2. Order per phase: port test → red → implement → green (TDD). A phase cannot close with its mapped tests `not-started`.
3. Waiver (`waived`) only for tests bound to out-of-scope infra (COM/TAEF/WinRT activation) → needs ADR row + replacement Rust test if behaviour is in scope.
4. Behavioural cross-check beyond WT tests: `vttest` scripted sessions + captured byte streams replayed through WT's `OpenConsole`/`wt` (if available locally, `windows/` build artefacts) vs Rust buffer dumps — golden files in `parity/golden/` (P03/P04/P09 own).
5. UI parity (P11–P17): spec-by-behaviour tests (action → state), plus GPUI visual snapshot tests with tolerance; XAML pixel identity not required (ADR-0005).

## 3. Audit tooling — `xtask` (P01 delivers the FULL command set; P19 only adds summary/fuzz glue)

`crates/xtask` (workspace member, no external deps beyond std/csv/serde/serde_json). Commands:

| Command | What it checks | Exit≠0 when |
|---|---|---|
| `cargo xtask audit --wave N` | barrier mode (regression-only; a missing previous `summary.json` = no regression check): fmt, clippy, `cargo build --release -p terminal`, `cargo test --workspace`, `ledger-check`, `tests-check` (join validity only; `not-started` rows reported, not failed), `stubs` (report only), no status regression vs the previous `parity/summary.json`; writes `audit-NNN.md` and updates `parity/summary.json` (P01 writes the round-0 file) | regression or red gate (NOT for incomplete work) |
| `cargo xtask audit --final` | strict: every §4 criterion; writes `audit-NNN.md` + `parity/summary.json` (fields: `round`, `rows_by_status`, `tests_by_status`, `stubs_by_crate`, `new_gaps`, `clean_streak`, `coverage_diff_line`, `coverage_diff_branch`) | any §4 criterion unmet |
| `cargo xtask ledger-seed [--tests]` | one-off seed of shards, `exclusions.csv` and `tests.csv` from `windows/src` (P01) | I/O or schema error |
| `cargo xtask merge` | merges per-phase shards into `parity/merged/*.csv` | schema or duplicate-id error |
| `cargo xtask cov --phase NN` | crates + owned paths come from `parity/phases.csv` (P01, derived from the plan matrix); runs from the git root (`terminal/`): `cargo +nightly llvm-cov --branch --cobertura --output-path target/cobertura.xml -p <crate>`, then `diff-cover target/cobertura.xml --compare-branch=$BASE --fail-under=90` (line) and xtask parses cobertura `condition-coverage` for lines changed vs $BASE (`git diff -U0`) to enforce branch >=75% (`coverage_diff_branch`); $BASE = `--base <ref>` or ref in `parity/baseline-ref.txt` (operator creates the baseline commit; xtask never commits); tooling installed in P01 (`cargo install cargo-llvm-cov`, nightly + `llvm-tools-preview`, `pip install diff-cover`); no nightly → line coverage only + ADR waiver | below threshold |
| `cargo xtask e2e` | runs rows of `parity/e2e.csv` (scenario, phase, command, `ci` or `manual`): executes every `ci` row; for `manual` rows requires the named checklist file under `reports/` to exist and be marked signed | any failing ci row or missing/unsigned manual checklist |
| `cargo xtask stubs [--path DIR]` | counts, per crate (or per directory with `--path`), matches of the regexes in the block below (after stripping comments); `#[ignore = "manual: <checklist file>"]` is exempt | count > 0 (`--final`) |
| `cargo xtask ledger-check [--root DIR]` | CSV schema valid; `verified` rows need non-empty `reviewed_by`/`reviewed_at` with `reviewed_by` != worker; every row has `phase`, and `rust_path` unless status is `not-started`; no orphan WT file (re-walk `windows/src` restricted to `*.cpp|*.h|*.hpp|*.idl|*.xaml`: every such file must appear in a shard `files.csv` or in `parity/exclusions.csv` with an ADR; other extensions — `.vcxproj/.props/.sln/.def/.rc/.inc/.cs/.resw/images/.json` — are not ledgered per file: build/project/packaging files are replaced by Cargo/`packaging/`, `.resw` en-US strings and `defaults.json` are consumed by P14/P07, per ADR-0001); every `verified` row has test_ids resolving in `cargo test --list`; every `replaced/out-of-scope` has existing ADR | any violation |
| `cargo xtask tests-check` | `tests.csv` vs `cargo test --workspace -- --list` join; counts ported/passing/waived vs WT total | broken join always; any in-scope row `not-started` only with `--final` |
| `cargo xtask include-graph` | greps IN-scope C++ for `#include` of OUT-scope dirs → candidate promotions | any referenced OUT file lacking an IN promotion row or ADR |
| `cargo xtask loc-ratio` | Rust LOC / C++ LOC per module (sanity vs expected ~0.6×; flags suspiciously tiny ports) | never (warning only: ratio < 0.25 on a `verified` row's module is listed for reviewer attention) |

Alias: `.cargo/config.toml` `[alias] xtask = "run -p xtask --"` (created in P01). Test naming rule: `wt_<suite>__<method>` (double underscore) so filters such as `cargo test -p core -- wt_adapter__` never match helpers like `wt_rect`; multiple filters go after `--`. Baseline gates (run by `audit` too): `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo build --release -p terminal`.

## 4. Stop criteria (all must hold)

1. merged `files.csv` + `symbols.csv`: 100% rows ∈ {`verified`,`replaced`,`out-of-scope`}; 0 `not-started|stub|partial|ported`.
2. `tests.csv`: 100% in-scope rows ∈ {`passing`,`waived`}; every waiver has ADR.
3. `cargo xtask stubs` = 0 across workspace; `#[ignore]` = 0 without ADR.
4. fmt/clippy/test/release-build green.
5. include-graph: no un-ledgered OUT-scope file referenced by IN code.
6. `cargo xtask e2e` green (vttest goldens, shell smoke, GPUI snapshots); `cargo xtask cov` meets diff coverage (line >=90%, branch >=75%) for every crate.
7. **Two consecutive `audit --final` rounds** report `new_gaps == 0` (new gap = any new ledger row, red test, stub, or reviewer FAIL); `clean_streak >= 2` computed in `parity/summary.json`.

## 5. Audit loop procedure (repeat until §4)

```
LOOP (triggered: at every wave barrier, and continuously in P19):
 1. RUN   cargo xtask audit --wave N (barriers) or --final (P19) → audit-NNN.md (mechanical gap list)
 2. SAMPLE-REVIEW  fresh `code-reviewer` subagent(s), one per module with rows newly `ported` since last round:
        - inputs: ledger rows + WT file(s) + Rust file(s) ONLY (no worker narrative)
        - task : diff WT logic vs Rust symbol-by-symbol (branches, constants, edge cases, error paths); verdict per row
        - coverage: 100% of rows for high-risk modules (adapter, parser, input, buffer, TerminalCore, ControlCore, settings
          layering); ≥25% random sample + all rows with loc-ratio warning elsewhere
        - PASS → status=verified ; FAIL → status=partial + gap note (file:line of divergence)
 3. TRIAGE new gaps → append ledger rows (never silently drop), assign to owning phase, reopen its Todo.
 4. FIX   owning phase workers (wave rules unchanged); then back to 1.
 5. EXIT  when §4 holds on 2 consecutive rounds. Record in plan.md `## Audit Log` (round, counts, new gaps, verdict).
```
Hard rule: a round that finds a gap resets the streak. No "declared complete" without `audit-NNN.md` evidence (Verification Gate). Max effort guard: if 5 consecutive rounds each add >20 gaps in the same module → escalate (User-Challenge: re-scope/ADR).

### Stubs regexes (the first two are applied to comment-stripped Rust; `// STUB` is applied to the RAW text because it is itself a comment marker)
```
\b(todo|unimplemented)!\s*\(
#\[ignore(?!\s*=\s*"manual:)
//\s*STUB
```

### Path conventions
Audit reports are numbered `audit-NNN.md` with NNN auto-incremented by xtask. `include-graph` promotions append rows to the owning phase shard and delete the matching `exclusions.csv` row (done by P19, or by the phase that promotes, serially at a barrier). `reports/…` always means `plans/20261026-0111-wt-full-port-master-plan/reports/`; `xtask` runs from the git root `terminal/`. Manual-checklist files named in phases (`reports/pNN-*-checklist.md`) are created by the operator at the wave barrier from the item list given in that phase's Test Strategy; `cargo xtask e2e` verifies existence + signature for the matching `manual` row of `parity/e2e.csv`.
